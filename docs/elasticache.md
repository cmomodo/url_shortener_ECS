# ElastiCache Redis

The API uses **Amazon ElastiCache for Redis** as a cache for short-code → URL lookups. PostgreSQL remains the system of record; Redis reduces load on RDS for hot redirects.

Terraform lives under `infra/modules/elasticcache/` and is wired from `infra/elasticCache.tf`.

---

## What changed (security upgrade)

The stack was upgraded from a plain single-node cluster to a hardened **replication group**.

| Area | Before | After |
|------|--------|--------|
| **Terraform resource** | `aws_elasticache_cluster` | `aws_elasticache_replication_group` |
| **Encryption in transit** | None | TLS required (`transit_encryption_enabled`, `transit_encryption_mode = "required"`) |
| **Encryption at rest** | None | `at_rest_encryption_enabled = true` |
| **Authentication** | None | `auth_token` (32-character password) |
| **SSM `REDIS_URL`** | `redis://host:6379` | `rediss://:<token>@host:6379` |
| **Security group** | API task SG attached to the cluster | Dedicated `elasticache` SG; ingress only from API, dashboard, and worker task SGs |
| **Task egress (6379)** | Whole VPC CIDR | ElastiCache SG only |

### What this does *not* include (yet)

- **High availability** — still a single cache node (`num_cache_clusters = 1`, `automatic_failover_enabled = false`) to keep dev cost low.
- **Secrets out of Terraform state** — ElastiCache has no write-only `auth_token` field; the token is generated by `random_password.redis_auth` and stored as sensitive state (same pattern as many ElastiCache deployments).
- **Local Docker** — `docker-compose.yml` still uses plain `redis://redis:6379` without TLS or auth.

## Architecture

```text
API (ECS) ──TLS + AUTH──► ElastiCache replication group (private subnets)
         ▲
         └── REDIS_URL from SSM SecureString (/url-shortener/redis_url)
```

Only the **API** container receives `REDIS_URL` today. Dashboard and worker security groups are allowed to reach Redis for consistency and future use; they do not mount the parameter in the current ECS task definitions.

Network path:

1. Task egress: TCP **6379** → `elasticache` security group (not `172.31.0.0/16`).
2. ElastiCache ingress: **6379** from `ecs_tasks`, `dashboard_tasks`, and `worker_tasks` security groups only.

## Terraform resources

| File | Purpose |
|------|---------|
| `infra/modules/elasticcache/main.tf` | Replication group, subnet group, `redis7` parameter group |
| `infra/elasticCache.tf` | Module call; passes private subnets, ElastiCache SG, and auth token |
| `infra/secrets.tf` | `random_password.redis_auth` (ElastiCache-safe character set) |
| `infra/ssm.tf` | SecureString `redis_url` built as `rediss://:…` |
| `infra/modules/vpc/main.tf` | `elasticache` security group and task egress rules |

Replication group settings (summary):

- Engine **Redis 7.1**, node type **`cache.t3.micro`**
- **TLS required**, **encryption at rest** enabled
- **`auth_token`** from `random_password.redis_auth`
- Daily snapshots (`snapshot_retention_limit = 1`)

## Application behaviour

In `app/src/db.py`, the client is created from `REDIS_URL`:

- If the URL starts with **`rediss://`**, the Redis client uses **`ssl_cert_reqs="required"`** (AWS ElastiCache in-transit encryption).
- Plain **`redis://`** is still supported for local development.

Cache keys use the prefix `url:` with a one-hour TTL (`CACHE_TTL = 3600`).

## Deploy and operations

### Apply

```bash
cd infra
terraform plan
terraform apply
```

**Expect the old cache cluster to be replaced.** The replication group gets a new primary endpoint and an empty cache. URL mappings still exist in PostgreSQL; redirects work but may miss cache until warmed.

### After apply

1. **Restart ECS tasks** (API at minimum) so they load the new SSM `REDIS_URL`.
2. **Smoke-test** — shorten a URL, hit the short link twice, confirm redirects and no Redis/TLS errors in API logs.

### Rotating the auth token

1. Taint or replace `random_password.redis_auth` (or change its value in a controlled migration).
2. Set `auth_token_update_strategy` to **`ROTATE`** on the replication group if AWS requires it for updates (initial create uses **`SET`**).
3. Update the SSM parameter and restart ECS tasks.

### Troubleshooting

| Symptom | Likely cause |
|---------|----------------|
| `Connection refused` / timeout | Security group or task not restarted after SG change |
| TLS / certificate errors | `REDIS_URL` still `redis://` or missing `ssl_cert_reqs` path |
| `NOAUTH` / authentication errors | Stale SSM value or token mismatch after rotation |
| Empty cache after deploy | Normal after replication group replacement |

## Local development

Docker Compose runs an unencrypted Redis service:

```yaml
REDIS_URL: redis://redis:6379
```

No code changes are required locally; the API only enables TLS when the URL scheme is `rediss://`.
